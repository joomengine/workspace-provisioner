# Versioned configuration contracts

`php tools/schema.php TYPE` prints a complete standalone JSON Schema (2020-12) for `operator`, `inventory`, `catalog`, `recipe` or `request`. The schema definitions are public runtime assets in `src/Schema.php`. Packages generate the same files under `schemas/TYPE.schema.json`; they require no network fetch of private configuration. For editor use from a source checkout, redirect the command into a local schema file.

Configure the editor's external schema association instead of adding `$schema` to an operator payload: unknown runtime payload fields intentionally fail. JSON Schema supplies structural/editor validation; `Config`, `Request`, `Recipe` and `WorkspaceComposer` additionally enforce safe paths, key decoding, authorization, topology, hashes and cross-field policy. A structurally valid payload is not permission to execute it. `php bin/workspace validate --config FILE` is the operator runtime validation command and does not provision resources.

The default `examples/recipe.standard.json` adds no customization. `examples/recipe.verify-cli.json` demonstrates a repeatable Joomla CLI capability check without private branding or data. Production import, compile and branding commands remain operator-selected and must match the selected JCB image's CLI contract. VM commands require separately approved helper digests; no example grants arbitrary VM shell execution.

The normal create request is a version-1 object with `request_id`, `workspace_id`, `tenant`, `action: create`, `name`, `catalog`, `profile`, `admin_email`, and one or more plain Ed25519 public `ssh_keys`. UUIDs are generated by the caller once and retained for retries. Subsequent actions use the same workspace ID and a new request ID; `replace-keys` additionally requires `ssh_keys`, and `restore` requires `backup_id` and optionally the explicit boolean `replace_existing`. Never send a private key, image selector, privilege, host path or command through a customer request.
